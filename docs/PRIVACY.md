# PRIVACY.md — 隐私与安全设计

> 本文件是本项目的**承诺清单**。任何功能设计若与本文件冲突，以本文件为准。
> 核心原则：**LOCAL FIRST —— 你的账单永远不离开你的设备。**

---

## 1. 六条不可妥协的承诺

| # | 承诺 | 实现约束 |
|---|---|---|
| 1 | **默认无账号、无登录** | App 首启不出现任何登录/注册界面；无用户体系表 |
| 2 | **完全离线可用** | 所有功能（导入/分类/统计/预算/备份）在飞行模式下可用；不设任何必需的网络请求 |
| 3 | **原始账单不上传** | 不存在任何上传账单文件的代码路径；无服务端 |
| 4 | **账单只存本地** | SQLite 位于 `getApplicationSupportDirectory()`，随 App 卸载而删除 |
| 5 | **不记录敏感标识** | 不存完整银行卡号、身份证号、密码 |
| 6 | **AI 只发聚合数字** | 见 §4，`FinancialSummary` 是唯一允许外发的数据结构 |

## 2. 数据流向图

```
        用户设备（唯一的数据容器）
┌──────────────────────────────────────────────────┐
│                                                  │
│  账单文件 (.csv/.xlsx)                            │
│        │                                         │
│        ▼  本地解析（内存）                         │
│  导入预览（内存，未落盘）                          │
│        │                                         │
│        ▼  用户确认                                │
│  SQLite（本地磁盘）  ◀── 统计 / 图表 / 分类         │
│        │                                         │
│        ▼  用户主动导出                             │
│  备份文件 (JSON/CSV/XLSX) → 用户自己选择存哪       │
│                                                  │
└──────────────────────────────────────────────────┘
                    │
                    │ ★ 唯一可能的外发通道（可选、默认关闭）
                    ▼
        仅聚合数字（无商户名、无订单号、无卡号）
```

**关键设计**：上图中唯一的对外箭头是**可选且默认关闭**的 AI 分析，且只发送聚合数字。
除此之外，App 不发起任何网络请求。

## 3. 禁止记录的数据

| 数据 | 处理方式 |
|---|---|
| 完整银行卡号 | 导入清洗阶段用正则 `\b\d{12,19}\b` 检测并**剥离**，`accounts.masked_number` 只存 `**** 1234` |
| 身份证号 | 正则 `\b\d{17}[\dXx]\b` 检测并剥离 |
| 密码 / 验证码 | 不采集、不存储、不在任何输入框出现 |
| 完整账单原文 | 仅 `transactions.raw_data` 本地留档（排查用），**导出备份时默认剔除** |
| 用户真实姓名 | 不采集 |

## 4. AI 功能的隐私边界（Phase 17）

### 4.1 允许外发：`FinancialSummary`

```jsonc
{
  "month": "2026-10",
  "income_cents": 520000,
  "expense_cents": 328642,
  "balance_cents": 191358,
  "transaction_count": 187,
  "category_statistics": [
    { "name": "餐饮", "amount_cents": 82160, "ratio": 0.25, "count": 52 }
    // ★ 只有分类名与金额，没有商户、没有单笔记录
  ],
  "daily_statistics": [
    { "day": "2026-10-01", "income_cents": 0, "expense_cents": 12800 }
  ],
  "trend": { "mom_expense_change": 0.128, "direction": "up" },
  "time_bucket_statistics": [
    { "bucket": "18:00-21:00", "amount_cents": 92300, "ratio": 0.28 }
  ],
  "budget_status": [
    { "category": "餐饮", "limit_cents": 80000, "used_cents": 62000 }
  ]
}
```

### 4.2 绝对禁止外发

| 禁止字段 | 原因 |
|---|---|
| 商户名称 | 可反推个人行踪与生活习惯 |
| 订单号 / 交易单号 | 唯一标识，可关联 |
| 银行卡号 / 账号 | 直接金融风险 |
| 完整交易记录（逐笔） | 等于上传全部账单 |
| 备注 / 地点 | 高度隐私 |
| `raw_data` | 包含以上全部 |

### 4.3 用户控制

- AI 分析**默认关闭**，需用户在设置中显式开启
- 开启前弹出**预览**：展示"即将发送的内容"，用户可逐项取消勾选
- 提供"AI 分析记录"页面，可查看历史发送内容与清除记录
- 不开启 AI 时，本地规则引擎仍可生成基于规则的分析文案（如"餐饮支出环比上升 18%"）

### 4.4 自然语言查询的边界

```
"我今年在咖啡上花了多少钱？"
   ↓ IntentParser（本地，规则/小模型）
   { metric: sum, dimension: category, filter: {category: 咖啡, year: 2026} }
   ↓ QueryBuilder（本地，SQL 模板白名单）
   SELECT SUM(amount_cents) FROM transactions WHERE ...
   ↓ SQLite（本地）  ★ 真实数据由本地数据库返回
   82160 分
   ↓ （可选）LLM 只把 "82160 分" 组织成一句人话
```

**铁律**：
1. 发往 LLM 的是**用户的问题**，不是数据
2. SQL 由**本地白名单模板**生成，**绝不让 LLM 生成 SQL 字符串**（防注入 + 防越权读取）
3. LLM 不参与任何数据检索

## 5. 日志规范

| 允许 | 禁止 |
|---|---|
| `解析失败：第 12 行，金额字段无法解析` | 打印整行原始内容 |
| `导入完成：成功 1234 / 重复 52 / 错误 8` | 打印交易列表 |
| `数据库迁移 v1 → v2` | 打印 SQL 参数中的金额与商户 |
| 错误堆栈（不含数据） | 打印 `raw_data` |

实现：日志统一走 `AppLogger`，在 release 模式下**默认只输出 WARN 及以上**，且对 message 做敏感模式过滤（卡号/身份证/长数字串自动脱敏）。

## 6. 备份文件的隐私

| 关注点 | 处理 |
|---|---|
| 备份是明文 | 在设置页明确告知："备份文件为明文，请自行妥善保管" |
| `raw_data` | 默认**不导出**；设置里提供"包含原始数据（不推荐）"开关 |
| 银行卡号 | 只导出掩码 |
| 分享 | 用 `share_plus` 由用户主动选择目标，App 不自动上传 |
| 位置 | 用户自选目录；不写入任何固定云盘路径 |

## 7. 恢复数据的保护

brief 第 23 条：**恢复数据前必须预览 + 确认，防止覆盖已有数据。**

```
选择备份文件
   ↓ 解析
预览页展示：
   ┌────────────────────────────────┐
   │ 备份包含：                       │
   │   交易      1,294 条             │
   │   分类         24 个             │
   │   分类规则      18 条            │
   │   预算           5 条            │
   │   备份时间  2026-10-01 10:23     │
   └────────────────────────────────┘
   当前库已有：交易 3,102 条

   恢复方式（必须显式选择）：
   ○ 合并（跳过重复，保留现有数据）  ← 默认
   ○ 覆盖（先清空现有交易，危险）
   ○ 取消
   ↓
   二次确认（覆盖模式需输入"覆盖"二字）
   ↓
   执行（单事务，失败回滚）
```

**默认选项必须是"合并"**，"覆盖"需要额外确认步骤。

## 8. 仓库与开发环境规范

### 8.1 `.gitignore` 必须包含

```gitignore
# 账单与数据库 —— 绝不入库
imports/
database/
backups/
*.db
*.sqlite
*.sqlite3
*.xlsx
*.xls
*.csv
*.tsv

# 用户数据导出
exports/
*.json.bak

# 但测试 fixtures 例外（全虚构数据）
!test/fixtures/**
!assets/seed/**
```

> 注意：`*.json` 过于宽泛会误伤 `pubspec.lock`（非 json）与 assets 里的必要 json。
> 因此**不全局忽略 `*.json`**，改为忽略 `exports/` 与 `backups/` 目录 —— 更精准。

### 8.2 提交前自检

- [ ] `git status` 中无 `.csv` / `.xlsx` / `.db` 文件
- [ ] `test/fixtures/` 内所有商户名以 `示例` 开头
- [ ] 所有单号以 `TEST-` 开头
- [ ] 无真实姓名、真实账号、真实手机号
- [ ] 无硬编码的 API Key（如未来接入 AI，Key 由用户填写并存本地，不入库）

### 8.3 参考项目踩过的坑

`zalexrose/FamilyFinanceManager` 把 397 KB 的 `database/finance.db` **提交进了仓库**。
本项目将 `.db` 列入 `.gitignore` 硬性拦截，并在 CI 检查中加一条：
`git ls-files | grep -E '\.(db|sqlite|csv|xlsx)$'` 必须为空（`test/fixtures/` 除外）。

## 9. Android 权限最小化

| 权限 | 是否需要 | 说明 |
|---|---|---|
| `INTERNET` | ❌ | 默认不申请。仅当用户开启 AI 分析后按需申请（或干脆用系统级按需授权） |
| `READ_EXTERNAL_STORAGE` / `READ_MEDIA_*` | ⚠️ | 仅在使用 `file_picker` 选择文件时需要；优先用 SAF（Storage Access Framework）避免申请宽泛权限 |
| 无障碍服务 | ❌ | 本项目**不使用**无障碍抓取（见 GITHUB_RESEARCH §4.3 的技术调研结论） |
| 通知监听 | ❌ | 同上，不在 v1 范围 |
| 短信读取 | ❌ | 同上，不在 v1 范围 |

> 技术调研（`lemon970/jizhang-app` 附带文档）结论：安卓上"自动抓取交易"的 5 条路线中，
> 无障碍/通知/短信均需高敏感权限且可靠性有限；**账单文件导入是唯一低难度、高可靠、免 root 的路线**。
> 本项目采用文件导入，因此**不需要任何敏感权限** —— 这是巨大的隐私优势。

## 10. 隐私承诺的用户可见表达

App 设置页顶部固定展示：

> **你的账单只属于你**
> · 不需要注册账号
> · 飞行模式也能完整使用
> · 账单不会上传到任何服务器
> · AI 分析（可选）只发送汇总数字，不含商户与订单信息

并提供两个一键操作：
- **清除全部数据**（二次确认，需输入"删除"二字）
- **查看数据去向**（展示 §2 的流向图，让用户亲眼确认没有外发通道）
